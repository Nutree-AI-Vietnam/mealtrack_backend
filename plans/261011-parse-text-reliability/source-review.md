## Design implications

Use a parse-specific physical policy inside the current handler correction loop, not food-name allowlists or globally changed reference tolerances. Identify authoritative edible mass from explicit canonical mass units and validated row mass; reject conflicts rather than increasing food mass to make macros fit. Preserve current density conversion for volumes.

The name-dependent energy-density heuristic in `nutrition_resolver.py:239–280` rejects unlisted foods above `4.5 * mass + 20` kcal (470 kcal for 100g), including plausible 480kcal/100g granola. Existing resolver tests deliberately protect potato/apple excessive-fat mismatches at `tests/unit/domain/services/test_nutrition_resolver.py:166–195`. Confirmed scoped decision: keep that helper/legacy-provider policy, but custom AI estimates use separate physical/subset validation without a food-name whitelist. Update `tests/unit/app/services/test_parse_text_custom_estimate.py:68–79`, whose 98.9g fat/100g potato case tests noun knowledge rather than impossible mass, to a truly impossible aggregate-mass case. Physical checks do not establish identity accuracy; reference precedence and real-provider evaluation remain necessary.

Stop all postvalidation item losses. Recover reference lookup failures with the valid original AI estimate; if no valid estimate exists, return the existing validation error for the entire parse. This invariant guarantees completeness relative to AI rows, not that the AI recognized every free-text ingredient. Measure explicit-list omission separately in provider evaluation; do not add another routine generation.

Validate complete cache envelopes and inject existing CachePort through API composition only after fidelity checks pass. Preserve architecture: app/domain do not import infrastructure settings. Pass settings/cache context through existing composition helpers.

Instrument stage time and physical attempts before attributing latency. Bound request waiting independently of the SDK per-attempt timeout. Cancellation must release DB contexts/provider tasks; optional persistence cancellation must not expose uncommitted reference IDs.
